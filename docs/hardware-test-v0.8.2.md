# v0.8.2 實機驗證清單

依風險排序：越前面的項目，越常被這次的改動碰到。每項寫明操作和預期結果；括號裡是 console 會出現的文字。

不符合預期時，請記下：
- 項目編號
- console 最後約 20 行
- 測試器「匯出支援 Log」的檔案
- 當下的 `src/controller_status.json`

## 0. 準備

- [ ] 0.1 主視窗「Flash FW」刷入 S2P-FW `1.0.9`，確認版本顯示為 1.0.9。
- [ ] 0.2 先備份 `src/config.ini` 和 `src/profiles/`，測完可以還原。

只有一支手把也可以測：需要「換手把」的項目，改成把手把關機再開機。重連後連線 ID 會改變，程式會視為連線已變更。

## 1. ESP32 連線（風險最高）

- [ ] 1.1 **一般重連：** 開啟連接程式，按手把任一鍵。
  - 預期：出現「找到已配對手把，正在重新連線。」→ 初始化 → 兩下連線震動，可以正常操作。
- [ ] 1.2 **SYNC 新配對：** 按住 SYNC。
  - 預期：出現「找到手把，正在配對。」→ 配對成功，可以操作。
- [ ] 1.3 **反覆開關機：** 手把關機、開機，重複 5 次。
  - 預期：每次都能重連，沒有卡在「搜尋中」。
- [ ] 1.4 **連線中途中斷（本次修正的孤兒連線）：** 看到「找到已配對手把」後，馬上關掉手把，或把手把拿到收訊範圍外。
  - 預期：約 15 秒內出現「等待手把連線逾時，重新搜尋。」或「控制器連線失敗。」；之後再開手把，要能正常重連，不需要重插 ESP32。
- [ ] 1.5 **連線中拔掉 ESP32：** 手把已連線時，拔掉 ESP32 的 USB。
  - 預期：console 不會直接關閉，而是顯示「ESP32（COMx）已中斷，連接程式已停止。請確認 USB 連接線後，在主視窗按「重啟連線」。」，並停在「按 Enter 鍵關閉...」；主視窗狀態顯示「● 未啟動」。
  - 接著插回 USB、在主視窗按「重啟連線」：舊的 console 關閉，新的連接程式啟動並重新連上手把。
- ~~1.6 啟動時拔掉 ESP32~~：啟動握手通常不到 1 秒，手動拔線很難剛好卡在這段時間，拔到的多半是 1.5 的情況。這條路徑已由單元測試涵蓋。
- [ ] 1.7 **閒置斷線：** 設定裡把閒置斷線設為 1 分鐘，放著不動。
  - 預期：出現「控制器因閒置而中斷無線連線；按任意鍵即可重新連線。」；之後按鍵就能重連。
- [ ] 1.8 **關閉時正確釋放：** 手把連線、遊戲正在震動時關閉 GUI。
  - 預期：震動立刻停止，console 跟著關閉（正常設計）。重新開啟主程式後，手把可以正常重連，不會因為還連在 ESP32 上而搜尋不到。
- ~~1.9 重複啟動~~：主視窗一律先關閉舊的連接程式才啟動新的，一般操作不會出現兩個，不需要實機測試。

## 2. 感測器校正

- [ ] 2.1 **完整三階段：** 主視窗「感測器校正」，依序完成陀螺儀、加速度計、磁力計。
  - 預期：每階段都顯示完成；不用重連就立即生效（陀螺儀靜止時不再漂移）。
- [ ] 2.2 **校正中關掉手把：** 陀螺儀靜止校正進行時關掉手把。
  - 預期：顯示「校正期間手把已斷線，請重新連線後再試。」，按鈕恢復可用，原本的校正資料不變。
- [ ] 2.3 **確認視窗開著時重連：** 第 2 階段（加速度計）的確認視窗開著時，把手把關機再開機，等它重新連上後按確定。
  - 預期：顯示「校正期間手把連線已變更」，加速度計校正不會開始，已完成的陀螺儀校正保留。
- ~~2.4 多支手把各自使用自己的校正~~：需要兩支手把，跳過（已由單元測試涵蓋）。
- [ ] 2.5 **剛校正完就存設定（本次修正）：** 陀螺儀校正一完成，就在主視窗按「儲存／套用」。
  - 預期：設定正常套用（「設定已即時套用」），不會跳出「即時套用設定失敗」。

## 3. 陀螺儀補償

- [ ] 3.1 **預覽量測：** 測試器 → 瞄準測試 → 3D → 補償預覽 → 設定調整後的速度 → 量測。
  - 預期：顯示建議倍率，接著顯示「補償倍率已儲存並套用至目前連線。」；主視窗的補償值同步更新。
- [ ] 3.2 **實際效果：** 套用補償後，在遊戲或測試器裡用陀螺儀轉動。
  - 預期：水平／垂直速度依倍率改變，實體搖桿不受影響。
- [ ] 3.3 **還原提示：** 倍率不是 1.00 時，開啟補償預覽或補償計算。
  - 預期：先詢問是否還原為 1.00；選「是」後，主視窗的兩軸都變成 1.00。
- [ ] 3.4 **量測中重連：** 補償預覽開著（或量測進行中）時，把手把關機再開機。
  - 預期：手把重新連上後約 1 秒內，預覽和量測自動關閉，倍率沒有被寫入；補償計算視窗也會一起關閉（這是目前的設計）。
- [ ] 3.5 **GUI 與測試器同時開著：** 主視窗有未儲存的其他修改時，在測試器寫入補償，再到主視窗按「儲存／套用」。
  - 預期：主視窗的補償值變成測試器寫入的新值，你自己的其他修改也一起保留，兩邊都沒被覆蓋。
- [ ] 3.6 **補償計算：** 輸入前後兩次耗時 → 按「開啟 S2P 補償設定」。
  - 預期：主視窗開啟補償設定；回到測試器重新開啟計算器時，剛才輸入的耗時仍然保留。
- [ ] 3.7 **滑鼠輸出：** 陀螺儀目標設為「滑鼠」。
  - 預期：補償按鈕隱藏或無法使用。

## 4. 陀螺儀行為

- [ ] 4.1 **圓形死區：** 回中模式下，斜向慢慢轉動手把。
  - 預期：斜向輸出方向正確，不會偏向單一軸。
- [ ] 4.2 **抑制突波：** 防晃模式選「抑制突波」、防晃 20 ms，設定一顆額外按鍵；一邊轉動一邊按這顆鍵。
  - 預期：按鍵瞬間的抖動被壓住，原本的轉動不會停頓。改選「暫停輸出」時，則是短暫停住。
- [ ] 4.3 **反死區預設：** 套用 System Default 或 General 方案。
  - 預期：反死區為 0。

## 5. 獨立模式（Android USB HID）

- [ ] 5.1 將補償不是 1.00、防晃模式為「抑制突波」的方案寫入 ESP32，並接上 Android 測試。
  - 預期：寫入成功；補償倍率、圓形死區、抑制突波的效果和電腦端一致。
- [ ] 5.2 （可選）用舊韌體寫入同一個方案。
  - 預期：顯示「目前 ESP32 韌體不支援…，請先更新韌體。」，不會寫入一半。

## 6. 設定視窗

- [ ] 6.1 **失去焦點提示：** 主視窗有未儲存變更時，切換到其他程式。
  - 預期：詢問是否儲存並套用；選「否」之後，要回到主視窗再離開才會再次詢問。
- [ ] 6.2 **系統預設方案：** 使用唯讀的系統預設並修改後切換到其他程式。
  - 預期：改成詢問是否另存為新方案。
- [ ] 6.3 **即時套用：** 連線中修改設定並儲存。
  - 預期：出現「設定已即時套用，不需重新連線。」

## 7. 其他連線方式

- [ ] 7.1 **Windows 原生藍牙：** 不接 ESP32，用電腦藍牙連手把（已配對與 SYNC 新配對各一次）。
- [ ] 7.2 **USB 有線：** 用 USB 線直接連手把，確認可以操作，關閉時正常釋放。
